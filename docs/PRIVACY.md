# Privacy

ClassMonitor is for enrolled school-managed devices during authorized lessons. Students always see the tray icon, which changes during a lesson, and a banner they cannot close while the screen is controlled, recorded or shown to the class. Students can end a session from the tray, and the teacher console does not restart it until the teacher starts another lesson. Recording and periodic snapshots require a console preference, a teacher confirmation, the Record grant in the enrollment, and that visible notice. No covert persistence, keyboard logging, credential harvesting, OS bypass or microphone/camera collection is implemented in this scope.

Screen frames, messages and lesson files stay between authorized LAN participants. Update checks contact the public GitHub release API and reveal ordinary request metadata; no student content is sent to GitHub. Audit records should contain actor/device identifiers, operation, classroom, time and outcome, not screenshots, keystrokes, passwords, chat text or file contents.

Recordings and snapshots stay in the configured folder on the teacher computer and are removed after the retention period, checked at startup and every minute. Recording stops at the storage limit. Schools must configure retention, access, approved directories and deletion policies. Existing historical recordings are not retroactively erased automatically. Privacy functionality, retention enforcement and storage protection require tests; open gates are recorded in FEATURE_MATRIX and PROGRESS. Never include desktop diagnostic screenshots in public repository or releases.
